# KV cache streaming

KV streaming follows Strata's host-backed residency cache. `DSV4F_KV_RESIDENT` defaults to **65536 compressed KV cells per CSA layer** (not raw tokens); `0` keeps the whole cache in VRAM. For example, `DSV4F_KV_RESIDENT=16384 ./run-server.sh` limits each CSA layer to 16384 resident cells. The full CSA history remains in pinned RAM, and the GPU loads only rows selected by attention, using CLOCK eviction and write-through updates. This preserves older context, rejected-draft rollback, and saved conversation state. Raw sliding-window KV, HCA KV and lightning-indexer keys remain on the GPU. When all CSA cells fit the limit, the regular resident path is used automatically; at the default 262144-token context, CSA's 4:1 compression fits 65536 cells, so streaming starts with a larger context or a smaller resident limit.

Streaming requires flash attention and a CUDA/HIP GPU, with Q8_0 (the launcher default) or FP16 keys and mapped pinned host memory. Additional pinned RAM holds the full compressed CSA cache. Decode stages only selected rows in bounded query groups. Like Strata, prefill temporarily stages the current layer's compressed history, reusing the normal optimized attention kernels; this workspace is included in graph reservation and the expert-cache VRAM budget. The launcher keeps host pinning enabled while streaming is configured. Run `ctest --test-dir build -R gpu-kv-stream-parity --output-on-failure` for the GPU parity/eviction/restore checks. HIP is validated on RX 7900 XTX; CUDA uses the same implementation but has not been tested on NVIDIA hardware.

## VRAM budgeting and MTP prefill

Target and MTP contexts reserve MMQ activation-quantization buffers and routed-row metadata in their GPU graph allocations. Expert-cache sizing sees these bytes before allocating its base cache or decode extensions. Prefill/decode workspace transitions release and reserve this storage with the corresponding graph.

Previously, MMQ allocated these buffers lazily from the backend pool. A 4096-token MTP prefill could request additional VRAM after the expert cache had already filled the available budget, causing an out-of-memory abort in `ggml_cuda_mul_mat_q`. More free VRAM after stopping the desktop also permits a larger automatic expert cache; it does not guarantee more space remains for an unreserved temporary allocation. Display allocations, pool reuse and allocator rounding can change which side of the allocation boundary a run reaches.

At the default single-sequence 262144-token context, both `DSV4F_KV_RESIDENT=65536` and `0` use the fully resident CSA path. Different outcomes with these settings alone do not demonstrate a streaming eviction error; compare the actual context, cache mode and VRAM allocations as well.

On HIP, `ctest --test-dir build -R gpu-mmq-reserved-workspace --output-on-failure` verifies dense, routed, broadcast and batched MMQ, including a 4096-token case, while rejecting every allocation from the temporary GPU pool. This catches missing reservations without changing the desktop session or exhausting display VRAM. The test also compares numerical results with the CPU backend and exercises graph replay.
